# SLH v{{VERSION}} — Local servers, Horizon and more reliable modpacks

This pre-release brings together the launcher changes made since the public 0.2.1 release: a persistent local-server library, experimental Horizon support, an expanded skin editor, older Minecraft versions and a compatibility audit of pack installation and launch.

## Local servers

- Create Java servers with Vanilla, Fabric, Forge, Quilt, NeoForge, Paper, Purpur, Leaf, Spigot, Bukkit or a custom JAR. Choose a concrete build, Java/JDK, memory, arguments, world, networking and access settings.
- Build Spigot/Bukkit through official BuildTools with an isolated Git configuration. Preview the launch command and accept the Minecraft EULA explicitly.
- Select a persistent main server folder. SLH discovers existing profiles and nested groups, remembers them across restarts and rescans without duplicating profiles or replacing server files. Ambiguous and missing profiles remain visible with their setup requirements.
- Use cards, icons or a list; search, sort, reorder, customize artwork and drag servers between logical groups. Grouping and reordering do not move the server folders.
- Share library and detail-page components with Minecraft instances, including the launch panel, configurable action tiles, compact context menus, settings cards and configurable tabs.
- Read current `server.properties` values, preserve unknown properties/comments and detect conflicting external edits before saving. Minecraft's own whitelist is distinct from a plugin's separate access controls.
- Edit the Minecraft whitelist, OP administrators and permission levels, player bans and IP bans while the server is stopped.
- Browse compatible plugins through Modrinth/CurseForge with version selection, dependency checks and backups. Incompatible files cannot be installed just because a project appears in search.
- Use a colored console with search, wrapping, copy/export, auto-scroll and a persistent command field, or open it separately. Stop saves the world; force termination is a separate confirmed action.
- Servers run in a separate `server-host` process. Closing the launcher leaves them running; reopening restores control and console access. Missing control is reported without pretending a live Java process stopped.
- Show server memory use, CPU load and uptime while the launcher is active, with explicit unavailable values rather than invented zero measurements.
- Export standalone start scripts. Server deletion has an explicit warning; it is not an automatic backup operation.

## Experimental Minecraft on Rust: Horizon

- Enable **Minecraft on Rust** in Advanced settings, then choose **Rust** when creating a compatible instance. The question-mark button links to the upstream Horizon repository.
- Browse compatible stable Horizon releases from GitHub instead of relying on one hard-coded release. Compatibility, the preparation Java requirement and pinned Minecraft metadata come from each release's `research-lock.json`.
- Verify the Horizon archive's SHA-256 and prepare the required client/server files and missing assets in isolated per-release folders. Republishing Java metadata does not overwrite a Horizon release's pinned inputs or the shared Java cache.
- Change the Horizon release for a stopped instance and reinstall its runtime while keeping game files. Existing installations retain their selected release and can launch without refreshing the catalog.
- Isolate Horizon settings from Java-instance synchronization, including wildcard rules, so native settings cannot overwrite Fabric/Forge settings.
- Integrate process status, stop controls and logs. Microsoft session data uses a temporary session file rather than command-line arguments or logs, with cleanup after use.

Horizon support is currently **Windows x64 only**, requires Vulkan and a Microsoft account owning Minecraft Java Edition, and does **not** support Fabric/Forge/NeoForge/Quilt Java mods. Java is needed for resource preparation; gameplay uses Horizon's native client. Future upstream archive or CLI changes may require another SLH update. [Horizon project](https://github.com/horizon-rust/horizon)

## Modrinth, CurseForge and game launch

- Resume interrupted Modrinth imports in the same instance, preserve overrides and existing configuration on retry, try alternate verified mirrors and serialize writes to shared download destinations.
- Reject unrelated ZIP files during CurseForge auto-import instead of treating every `manifest.json` as a Minecraft pack.
- Choose an eligible runtime file on Modrinth even when no primary file is marked; never fall back to a sources/dev/javadoc JAR or signature.
- Accept a selected Modrinth pack version when the project was addressed by its slug; compare canonical project identities.
- Check incompatibilities within the planned dependency graph as well as installed content, and respect exact-version incompatibility declarations.
- Normalize CurseForge loader names and exclude environment labels from loader metadata. Exclude server archives from client version selection and reject them before client installation.
- Update required dependencies without leaving old active JARs behind, including recognizable manually installed/cross-provider duplicates. Keep disabled and unrecognized files; failed downloads preserve the original content.
- Fix duplicated legacy Forge arguments such as `--gameDir` and `--assetsDir`, which could stop LaunchWrapper before mods loaded. Merge new profiles correctly and normalize existing string-argument profiles in memory, preserving repeatable arguments such as `--tweakClass`.
- Keep authors' distribution restrictions and exact hash checks for manual downloads. Missing required files remain actionable installation errors rather than silently producing a ready-looking incomplete pack.

## Diagnostics, downloads and storage

- Save redacted installation, download, launcher and game-process failure reports in the launcher's `crash` folder. Show the failing file and underlying error and provide report links from errors, notifications and Advanced settings.
- Preserve crash-report paths through typed launch events so the report action reaches the notification.
- Add structured launch-preparation timings for synchronization, credentials, runtime/arguments and total preparation. These distinguish work in SLH from loading inside Minecraft.
- Improve parallel downloads and the collapsible download history. Storage cleanup previews candidates, verifies launcher ownership/checksums and rechecks before removal, preserving worlds and unrelated files.
- A reported 26.4 Snapshot 6 startup delay was traced to a 64.6-second Datafixer pass in the game log. An isolated repeat after compilation finished measured approximately 0.56 seconds for both the snapshot and 26.3. This is a diagnostic result, **not a claimed universal snapshot speedup**; no speculative JVM tuning is applied.

## Skins, appearance and interface

- Add an offline-account skin gallery, PNG upload, arm-model selection and avatar refresh, with local skin support for Java 1.7.2+. Visibility to other players depends on their skin system.
- Include the nine default Minecraft skins. Use static thumbnails in the gallery to reduce rendering work, compact cards and fixed bottom actions.
- Open the skin editor on **Skin**, keep **Cape** directly accessible for Microsoft accounts, preserve an unapplied cape preview when switching tabs and retain the selected character rotation when changing skin/model.
- Keep Ely.by appearance management on its website; unavailable offline/Ely.by cape controls stay disabled.
- Apply the updated neutral character pose to the editor and home portrait mode.
- Make instance and server context menus consistent, compact and icon-based. Library menus open to the right while remaining inside the window.
- Clarify Compact navigation (beta) and extend RU/EN/DE labels for the new features. Custom language files continue to receive missing labels through embedded fallbacks.

## Minecraft version selection

- Select **Releases, Snapshots, Beta and Alpha** independently in a compact horizontal control. Only releases are enabled by default.
- Install legacy Alpha/Beta versions with their appropriate Java and legacy resource layout. Historical verification covered Alpha 1.2.6 and Beta 1.7.3 on Windows; this does not certify every historical version.

## Core, updates and compatibility

- Keep shared logic in `crates/slh-core`, with Tauri as the desktop adapter. Include the standalone server host, forward-only database migrations, process recovery and content diagnostics.
- Synchronize npm, Tauri, Rust and preview version metadata at **{{VERSION}}**.
- Fix macOS's standard `/var` and `/tmp` aliases being rejected as unsafe paths during staging, server discovery and cleanup. Only the known system mappings are accepted; nested/user-created symbolic links remain blocked.
- Preserve instances, accounts, settings and custom language files across application updates. Existing 0.2.1 in-app updates use signed update payloads; portable archives remain available for manual replacement.
- Bedrock remains experimental and Windows-only; this release does not claim Horizon or Bedrock support on macOS/Linux.

## Verification and limits

Local Windows validation passed the UI audit, TypeScript/Vite production build, 166 frontend tests, 209 Rust core tests, 11 Tauri adapter tests and 10 targeted Playwright scenarios. Five Rust tests require external/live environments and remain explicitly ignored. Release CI builds and tests Windows, Linux and both macOS architectures; automated builds do not replace physical-device testing or certify every modpack. macOS/Linux device testing is not claimed.

Keep backups of important worlds when testing a prerelease. CurseForge's version picker still exposes its first API page (up to 50 files); older files may be outside that window.
