# Horizon в SLH

В «Настройки → Дополнительно» включите «Майнкрафт на Rust». В новой сборке выберите версию Minecraft, ядро Rust и совместимый релиз Horizon. «ЧаВо? — FaQ?» открывает https://github.com/horizon-rust/horizon.

Первая интеграция поддерживает Windows x64 и стабильные релизы Horizon с проверяемым Windows x64 архивом на GitHub. Нужна видеокарта с Vulkan и активный Microsoft-аккаунт с Minecraft Java Edition. SLH устанавливает обычные файлы Minecraft из Mojang, скачивает архив Horizon, проверяет закреплённый SHA-256 и запускает его horizon-prepare с версией Java из research-lock.json выбранного релиза. Управляемая Java устанавливается согласно существующим настройкам SLH. Java нужна для подготовки, игра запускается нативным horizon-client.exe.

Для подготовки SLH загружает описание Minecraft и индекс ресурсов, закреплённые в `research-lock.json` релиза Horizon. Это позволяет подготовить игру, даже если Mojang повторно опубликовала описание той же версии. Эти файлы и недостающие ресурсы сохраняются отдельно в сборке Horizon; общий индекс ресурсов и метаданные Java-сборок не заменяются.

Все файлы Horizon и журналы подготовки находятся в `horizon/` внутри сборки. Миры, настройки игры, ресурспаки и журналы самого клиента находятся в обычной папке `game/` этой сборки. Чужие миры автоматически не импортируются. Сессия Microsoft передаётся через временный файл, который клиент удаляет после чтения; SLH также удаляет его при завершении процесса. Токен не попадает в аргументы или журналы.

Fabric/Forge/NeoForge/Quilt и Java-моды не поддерживаются. Версия Horizon меняется в настройках остановленной сборки: выберите релиз и примените его, затем установите сборку заново. Файлы игры сохраняются. Для другой версии Minecraft создайте отдельную сборку: автоматического преобразования миров при обновлении нет. Отключение функции сохраняет её сборки и файлы, но блокирует установку и запуск.

Настройки Horizon изолированы от общей синхронизации Java-сборок, включая правила «Все сборки». Его `options.txt`, список серверов и другие файлы не копируются в общее хранилище и не заменяются файлами Java Edition.

Если подготовка завершилась ошибкой, откройте папку сборки и журналы `horizon/prepare-*.log`, устраните причину и повторите установку. После неполной установки сборка остаётся в состоянии ошибки. Контрольные суммы исходных файлов дополнительно проверяет сам Horizon по своему research-lock.json.

Обновление лаунчера в E:\SLH выполняется заменой SLH.exe с резервной копией прежнего файла. Пользовательские языковые файлы не заменяются: новые ключи берутся из встроенного каталога.

Каталог проверяет до трёх страниц последних GitHub-релизов и обновляет кеш через пять минут. Релизы самого лаунчера, nightly и архивы без SHA-256 не предлагаются. При временной недоступности GitHub отображается кеш; установленная игра запускается без обращения к каталогу. Для ремонта закреплённой старой версии используется прямой запрос по тегу, даже если её уже нет в последних страницах каталога.

Совместимость, контрольная сумма метаданных Minecraft и требуемая Java читаются из research-lock.json тега, а при установке дополнительно сверяются с research-lock.json внутри проверенного архива. Ресурсы и импорт каждого релиза хранятся отдельно. Старые сборки без loaderVersion продолжают использовать release из своего installed.json; они не переводятся на новый релиз автоматически.

Новые релизы (например, 0.3.0 для Minecraft 26.4) появляются без изменения констант SLH, если сохраняют поддерживаемый формат архива, research-lock.json и интерфейс командной строки подготовки. Несовместимый формат останавливает установку с ошибкой; гарантировать поддержку неизвестных будущих изменений upstream невозможно.
# Локальные серверы Horizon

При включённом «Майнкрафт на Rust» в дополнительных настройках в выборе ядра локального сервера доступен `Horizon (Rust · Beta)`. Выбираются совместимая версия Minecraft и закреплённый релиз Horizon (поддерживаемая линия — v0.2.95 и новее). При отключении тумблера новые серверы Horizon не создаются, установка и запуск блокируются; существующие папки сохраняются.

Официальный `horizon-server` — управляющая оболочка над движком `horizon-client --dedicated --nogui`. SLH запускает этот же выделенный движок через собственный `slh-server-host`, чтобы консоль, штатный `stop`, перезапуск, журнал и отслеживание процесса работали в библиотеке локальных серверов. Готовность определяется стандартной строкой `Done (...)`, а не самим появлением процесса. Оболочка Horizon и её отдельная веб-панель не запускаются.

Установка повторно использует проверку SHA-256 архива релиза и подготовку ресурсов Horizon. Файлы размещаются в `.slh-horizon/horizon` внутри папки сервера; клиентская сборка не создаётся в библиотеке и её миры не используются. Java и Microsoft-аккаунт с Minecraft нужны для подготовки ресурсов по существующим правилам интеграции SLH. Сам выделенный сервер запускается нативно, без JVM и без окна игры. Параметры `server.properties` и явное принятие EULA используются как у остальных серверов SLH.

Java-моды, плагины Bukkit и JVM-флаги не применяются. Ограничение памяти Java не является ограничением памяти нативного процесса; страница JVM для этого ядра заменена управлением консолью. К существующим мирам рекомендуется относиться как к мирам экспериментального ядра: совместимость конкретного релиза определяется Horizon.

Источник устройства сервера: [hosting.md](https://github.com/horizon-rust/horizon/blob/main/docs/hosting.md), [engine.rs v0.2.97](https://github.com/horizon-rust/horizon/blob/v0.2.97/crates/horizon-server/src/engine.rs). Опциональная проверка выделенного движка: `python scripts/test-horizon-dedicated.py --release <папка-релиза>`. Она создаёт отдельный временный мир, слушает только 127.0.0.1, проверяет Minecraft status, передаёт `list`, `save-all`, `stop` и сохраняет журнал теста; исходные ресурсы только читаются.


Создание сервера закрывает диалог после сохранения профиля; установка продолжается в фоне. Если название пустое, кнопка создания переводит фокус на это поле и подсвечивает его.

Для Horizon-сервера запускается только обязательная подготовка `--prepare`, без звуков, панорам и прочих клиентских дополнений. Подготовленные ресурсы существующих клиентов и серверов SLH могут копироваться в отдельную папку нового сервера, если совпадают релиз и SHA-256 архива, а файлы проходят проверку контрольных сумм из манифеста. При отсутствии подходящих ресурсов выполняется полная подготовка, которая может занимать несколько минут.

В настройках локальных серверов режим портов применяется к новым профилям: общий порт или следующий незанятый среди сохранённых профилей, начиная с порта по умолчанию (25565). Это не резервирует порт на уровне ОС: перед запуском по-прежнему проверяется его доступность. При обновлении списка серверов свойства читаются из актуального `server.properties`, поэтому изменения порта вне SLH отображаются без перезаписи файла.
