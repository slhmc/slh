# Постоянная библиотека серверов SLH 0.2.1

Эта реализация заменяет временное обнаружение и подключение серверов из предыдущей рабочей области. Общая библиотека и страница сервера используют компоненты клиентских сборок. Публикация на GitHub не выполнялась.

## Каталог и данные

Выбор основной папки сразу сохраняется через ядро и запускает синхронизацию. Синхронизация также выполняется при запуске приложения и ручном обновлении. Профили сопоставляются по нормализованным путям; оформление, идентификаторы и ручная группировка не сбрасываются. Ошибки распознавания возвращаются отдельно. Сервер без достаточных параметров получает готовность «Требуется настройка», а недоступная папка — «Недоступен»; готовность отделена от состояния процесса. Автоматическая установка ядра поверх импортированного сервера запрещена.

Обнаружение читает конфигурацию, метаданные JAR и стартовые скрипты, не выполняя их. Рекурсия ограничена восемью уровнями и 2000 каталогами, не обходит ссылки/junction и останавливается на найденном сервере. Миры, библиотеки и плагины внутри сервера не превращаются в группы. EULA не принимается автоматически.

Миграция 0023 добавляет логические коллекции, привязки профилей, готовность и оформление, переносит старые физические группы в представление. Старые миграции не изменены. Все новые групповые операции работают с базой SLH, не перемещая каталоги. Удаление группы поднимает содержимое к родителю и сохраняет отметку удаления, чтобы сканирование её не восстановило. Старые профили вне выбранного корня остаются в «Других расположениях».

## Общие компоненты интерфейса

`LibraryChrome` используется обеими библиотеками: каркас, панель инструментов, виды, заголовки групп, поверхности карточек, оформление значков, контекстные меню и боковая панель. Обработчики серверных операций остаются отдельными. `DetailFrame` и `DetailTabs` используются страницами сборки и сервера.

Библиотека серверов сохраняет вид, сортировку, ручной порядок, раскрытие групп, текущую группу, выделение и положение боковой панели. Поддержаны вложенная навигация, цепочка групп, перетаскивание серверов, порядок групп и ручная сортировка. Метаданные значка и цветов сохраняются в SLH. Исходный `server-icon.png` читается для отображения и не переписывается при выборе библиотечного оформления.

Страница сервера открывается на «Обзоре». Запуск со встроенной консолью открывает «Консоль». Четыре вкладки с иконками — «Обзор», «Настройки», «Консоль», «Плагины» — первоначально наследуют расположение клиентских вкладок, а затем сохраняют независимые настройки. Настройки собраны в карточках шириной до 860 px; консоль имеет собственную прокрутку и доступную строку команды. На узком экране вывод сохраняет полезную высоту, а страница прокручивается целиком.

## Итоговые проверки

- `npm run check:ui`: 1788 значений каталога, без ошибок.
- `npm run build`: успешно; предупреждение размера существующего JS-пакета остаётся.
- `npm test`: 135 тестов.
- Rust core: 172 теста, два прежних ignored; Tauri: 11 тестов.
- Playwright: 25 сценариев, включая реальные pointer-перетаскивания, сохранение после перезапуска, клиентскую навигацию, плагины и узкую консоль.
- Настоящий Windows EXE: изолированная база, запуск и закрытие SLH без остановки Java, восстановление управления и истории, `stop` с сохранением мира, плагины через native IPC, постоянный корень `E:\servers`, 21 распознанный сервер, семь серверов в группе `gdz`, оформление и ручная группировка после повторного открытия.
- Контрольные файлы настоящих серверов до и после сканирования и операций над логическими группами совпали. Настоящие пользовательские серверы не запускались.

Машинные результаты и SHA точного проверенного EXE: `artifacts/native-server-smoke-result.json`, `artifacts/server-library-update-result.json`, `artifacts/server-library-installed-preservation.json`. Резервная копия EXE и базы создаётся до локального обновления. При настройке установленной базы допускаются только новые серверные метаданные и настройка корня; остальные таблицы, настройки и файлы проверяются отдельно.
