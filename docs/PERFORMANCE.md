# Оптимизация SLH — 4 октября 2026

## Поднастройка FPS персонажа — 5 октября 2026

В «Внешний вид» под переключателем «Красивое Главное Меню» добавлен ползунок FPS персонажа: 1–60 и крайнее положение «Безлимит». При перетаскивании значения 28–32 прилипают к 30; клавиатура позволяет точно выбрать любое целое значение. Нажатие отметки 30 быстро выбирает 30 FPS. Запись в настройки происходит при завершении ввода, а не на каждом шаге перетаскивания.

Значение хранится в `appearance.homeCharacterFps` (0 означает безлимит), отсутствие поля в старых настройках даёт 30 FPS. Rust проверяет диапазон и целочисленность. Лимит применяется к idle и взаимодействию; безлимит снимает ограничение приложения, оставаясь в рамках браузерного requestAnimationFrame и частоты дисплея. Остановка отрисовки при сворачивании сохранена. При изменении FPS новый renderer получает новый canvas.

Проверки: production frontend собран, 41 frontend-тест и 2 теста Rust-настроек прошли. Новые тесты проверяют магнит, точный ввод стрелками, безлимит, передачу лимита renderer и валидность сохранённых значений. Computer-use, визуальная проверка native-окна и замеры нагрузки в этом изменении не используются по просьбе пользователя.

## Исправление белого окна и фоновой работы

### Возврат 3D с idle и исправление загрузки скина

По новому запросу пользователя на главной оставлена только `HeroIdleAnimation`: без эмоций по нажатию, движения за курсором и автоматического вращения. Перетаскивание вращает персонажа, Ctrl + колесо меняет масштаб. Idle ограничен 30 FPS, активное вращение и затухание камеры — до 60 FPS; намеренное ограничение idle не считается поводом снижать качество изображения. В скрытом или свёрнутом окне анимация и render loop остановлены.

Исправлен жизненный цикл холста при асинхронной замене стартового скина: новый renderer получает новый canvas. Старый renderer освобождает WebGL-контекст, поэтому повторное использование его canvas могло приводить к 2D fallback до перехода в библиотеку и обратно. Перед dispose снимается обработчик потери контекста; поздняя загрузка скина после ухода со страницы не восстанавливает renderer. Регрессионный тест проверяет замену холста и игнорирование позднего события старого контекста.

Проверки этого изменения: production frontend собран, 36 frontend-тестов прошли, включая регрессию загрузки скина, паузу/возобновление, отсутствие эмоций по нажатию и сохранение качества при 30 FPS. Предупреждение jsdom о недоступном Canvas в тесте политики качества не влияет на результат: тест не создаёт настоящий WebGL renderer.

Release через `npx tauri build --no-bundle` установлен в `E:\SLH`; SHA-256 `912A840E0B227FE11B670EF9756E62EC07A0416A6481C16D0E088532B0C8FE3B`. Хеши файлов в корне `data` непосредственно до и после обновления совпали. В native-окне проверены первое открытие главной с загрузкой аккаунтного скина, переход главная → библиотека → главная, повторный запуск сразу на главной, вращение перетаскиванием и восстановление после сворачивания. ## Что изменено

- Главный Mine3D по последнему запросу показывает объёмного персонажа с idle до 30 FPS и взаимодействием до 60 FPS. Эмоции по нажатию удалены; при скрытии окна цикл полностью остановлен. Качество исходного изображения и аппаратное ускорение сохранены.
- Превью skinview3d используют `renderPaused`, обновляются по событиям и освобождают геометрию, материалы, composer и WebGL-контекст. Поздняя загрузка изображения после закрытия больше не создаёт текстуры.
- Общий адаптер активности учитывает `document.hidden` и native `isVisible`/`isMinimized`, очищает поздно зарегистрированные обработчики и не сообщает повторно неизменное состояние.
- Мониторинг: CPU/ОЗУ/ввод-вывод раз в 3 секунды, поиск дерева процессов раз в 10 секунд, GPU не чаще раза в 5 секунд (при трёхсекундном опросе — обычно раз в 6). В скрытом окне опрос остановлен. Подробные показатели чужих процессов не запрашиваются.
- Размер папки обновляется при открытии после истечения кеша и после файловых операций; минутного обхода больше нет. Кеш инвалидируется и когда главная закрыта.
- Проверка завершения Minecraft на Windows использует `OpenProcess`/`GetExitCodeProcess` вместо запуска `tasklist` каждые 2 секунды.
- Страницы, мастер создания сборки, «Обзор» и skinview3d загружаются по необходимости.
- Portable использует системный Evergreen WebView2, без Fixed Runtime и локального override. При отсутствии runtime до создания окна предлагается официальная страница загрузки; отказ завершает запуск. NSIS/MSI используют `downloadBootstrapper`.

## Интерфейсы

`get_system_metrics` принимает необязательные `scope: "launcher" | "system" | "all"` и `metrics: ("cpu" | "memory" | "network" | "gpu" | "disk")[]`. Без аргументов возвращает прежний набор показателей. Имена и типы полей ответа сохранены. Первый CPU/I/O-сэмпл после смены области или длинной паузы — `null`, чтобы не выдавать усреднение за период скрытого окна.

`get_launcher_storage_usage` принимает необязательный `force: boolean`. Frontend применяет свой минутный кеш и принудительно пересчитывает значение при промахе кеша. Память лаунчера подписана как сумма working set процессов: общие страницы могут учитываться несколько раз. Ввод-вывод не назван сетевым трафиком.

`SLH.exe --check-webview-runtime` проверяет доступность runtime тем же loader, не создавая окна: код выхода 0 при наличии, 2 при отсутствии. Portable-скрипт удаляет прежний runtime только после успешной проверки и отсутствия процессов из целевой папки; существующие данные сохраняются без `-CleanData`.

## Следующий этап: Linux/macOS

Нужно адаптировать загрузку Temurin (сейчас `os=windows`, ZIP и Windows-архитектуры), правила Minecraft/libraries/natives (есть Windows-проверки), executable permissions и архивы Unix, хранение секретов вместо DPAPI, пользовательские пути и упаковку. Windows-specific prevent-default, уведомления и Bedrock требуют платформенных адаптеров. Linux использует WebKitGTK, macOS — WKWebView; Apple Silicon требует ARM64 Java и native-библиотеки для соответствующих версий игры. Полноценная поддержка этих платформ этой сборкой не заявляется.

Если память после native-замеров останется неприемлемой, следующий шаг — измеряемый прототип UI без WebView с повторным использованием Rust-логики. Выбор UI-движка и полный перенос интерфейса в текущую оптимизацию не входят.
