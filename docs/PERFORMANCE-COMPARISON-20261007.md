# Сравнение старого и нового SLH, 7 октября 2026

Главная с idle-персонажем 30 FPS почти не стала легче по CPU. Основной подтверждённый результат — уменьшение working set свёрнутого окна. Значительного уменьшения private bytes нет; цель низкой нагрузки открытой главной не достигнута.

## Условия

Сборки запускались последовательно, без одновременного конкурирующего SLH: старая `E:\SLH\SLH.exe`, новая `artifacts/tauri-optimized-data-20261006/SLH.exe` на отдельной копии данных. Хеш новой соответствует финальному portable-пакету от 7 октября. Сторонняя тестовая x86-копия закрыта перед измерениями.

В обоих случаях: основной аккаунтный скин, 30 FPS, масштаб интерфейса 90%, окно 1463×775 логических пикселей, показанные метрики лаунчера включены, активных загрузок нет. Настройки FPS и внешнего вида прочитаны из SQLite в режиме read-only. Скин и ракурс визуально совпадают. Компиляция и тесты во время измерений не выполнялись. Другие пользовательские приложения оставались запущенными; это не лабораторный изолированный тест.

Для каждого сценария: 60 секунд прогрева, затем не менее 180 секунд наблюдения, выборка примерно каждые 3 секунды. Всего один проход каждого сценария. Отдельный Rust-процесс и 7 принадлежащих ему WebView2-процессов; Minecraft и WebView2 других приложений исключены. CPU нормализован по 8 логическим процессорам. Средние взвешены по фактической длительности выборок.

## Результаты

| Показатель | Старая | Новая |
| --- | ---: | ---: |
| Главная 30 FPS, CPU | 4,057% | 4,004% |
| Главная, GPU WebView2 | 2,083% | 3,073% |
| Главная, суммарный working set | 498,5 MiB | 485,6 MiB |
| Главная, суммарные private bytes | 360,1 MiB | 357,9 MiB |
| Свёрнуто, CPU | 0,0171% | 0,0107% |
| Свёрнуто, GPU WebView2 | 0% | 0% |
| Свёрнуто, суммарный working set | 476,6 MiB | 118,8 MiB |
| Свёрнуто, суммарные private bytes | 336,0 MiB | 329,7 MiB |

GPU — наиболее загруженный движок группы принадлежащих процессов WebView2, не общая загрузка видеокарты. У Rust-процесса GPU-счётчик недоступен. Более высокий GPU новой версии в этом проходе требует повторной проверки; одного прохода недостаточно для вывода об устойчивой регрессии.

Working set свёрнутой копии снизился примерно на 75%. Это не означает освобождение 75% выделенной памяти: private bytes снизился лишь на 1,9%. Low memory target / приостановка WebView2 главным образом сократили резидентные страницы; working set также может повторно учитывать общие страницы между процессами. GPU-ресурсы не измерялись отдельным счётчиком видеопамяти.

На главной CPU WebView2 снизился с 3,798% до 3,520%, но CPU Rust-процесса вырос с 0,258% до 0,484%, почти компенсировав выигрыш. Следующая оптимизация требует профиля встроенного мониторинга и 3D-отрисовки, а не заявления об уже достигнутом низком потреблении. Предел ≤1% CPU для главной с текущей idle-анимацией в этом сравнении не достигнут.

После замера новой свёрнутой версии окно восстановлено: интерфейс и 3D-персонаж появились снова без перехода в библиотеку. При восстановлении размер окна изменился; такой же эффект наблюдался у старой версии. Все измерения главной завершены до сворачивания, при одинаковом размере. Полная проверка вращения/масштаба после восстановления и 20 циклов не выполнена.
