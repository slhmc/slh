# SLH: правила интерфейса

Актуальные решения UX-аудита, серверных настроек, поиска и системного оформления: [внешний вид и поведение](INTERACTION_CONTRACT.md). При расхождении с историческими описаниями ниже используйте это уточнение.

В обзоре локального сервера блок нагрузки показывает занятую физическую память процесса Java в МиБ, CPU в долях мощности всего компьютера (0–100%) и время работы. Это показатели процесса, а не лимит или занятая куча JVM. Сбор выполняется по запросу раз в две секунды только в активном обзоре; при смене вкладки или скрытии окна опрос прекращается. Процесс проверяется по PID и времени запуска; новый запуск получает отдельную базу CPU. До первого замера и после остановки показывайте «—», а не нулевую нагрузку. При запуске вне SLH без известного процесса показатели недоступны.

Панель состояния содержит сведения о лаунчере, Java, загрузках, хранилище и папке данных. Список допустимых элементов задаёт `homeStatusItems`; неизвестные идентификаторы старых настроек игнорируются без изменения пользовательского файла. Панель не запускает периодический сбор показателей использования ресурсов.

Этот файл — источник правил для новых экранов и окон. Стиль SLH сохраняет пиксельный шрифт Pixeloid Sans, графитовые поверхности, настраиваемый акцент и компактные элементы управления. Используйте существующие React-компоненты и CSS Modules.

В рабочей области сервера кнопка «Библиотека» находится в шапке. Кнопка «Папка» повторяет поведение библиотеки сборок: название короткое и постоянное, значок соответствует текущей вкладке. Обзор и настройки открывают корень сервера, плагины — `plugins`, консоль — `logs`. Дополнительные действия консоли собраны в общем диалоге; в строке поиска остаются автопрокрутка и открытие действий. При смене запуска очищайте вывод и курсор предыдущего запуска, определяя запуск по идентификатору, а не только по состоянию сервера или номеру строки.

Библиотека серверов хранит последний список и значки в памяти между переходами. При возвращении сразу показывайте сохранённые карточки, выбранную группу, поиск и боковую панель; обновляйте данные в фоне. Первую загрузку и сканирование начинайте после получения bootstrap, сохраняя результат. Повторное фоновое сканирование при входе допускается через 30 секунд; ручное обновление сканирует сразу. Ошибка обновления не должна скрывать уже показанный список.

Перед запуском проверяйте сохранённый JAR. Если он отсутствует или его встроенная версия изменилась, общий диалог предлагает найденное ядро и показывает переход версии Minecraft и требуемую Java. «Нет» отменяет запуск без изменения профиля; «Да» обновляет только сведения о ядре и план запуска, сохраняет прежний профиль в резервную копию и продолжает запуск. Память, JVM-флаги, миры, плагины, `server.properties` и скрипты не переписываются. Кандидаты ищутся только в корне сервера; выбранный вручную JAR также проверяется. Изменение файлов или профиля после показа диалога требует повторной проверки.

## Тема и содержимое

- Цвета интерфейса берите только из `--color-*`. Тема строится в `src/lib/theme.ts` и применяется к документу, включая модальные окна. Значения по умолчанию находятся в `src/styles/tokens.css`.
- Основные роли: `bg`, `surface`, `surface-2`, `border`, `text`, `text-muted`, `accent`, `accent-hover`, `accent-pressed`, `success`, `warning`, `error`, `info`, `focus`, `link`, `overlay`, `shadow`.
- Для состояния используйте цвет, текст и значок. Ожидание действия игрока — предупреждение; сбой — ошибка. Цвет не должен быть единственным признаком состояния.
- Скины, обложки, значки сборок и сцены с персонажем сохраняют свои цвета. Консоль использует собственную палитру. Названия и описания проектов от провайдеров не переводите.
- Старые пользовательские палитры сохраняют базовые цвета; отсутствующие цвета состояний вычисляются из прежнего акцента. Новые пресеты сохраняют и цвета состояний.

## Размеры, текст и состояния

- Отступы: 4, 8, 12, 16, 24 px (`--space-*`). Высота управления — `--control-height`, отступы панелей — `--panel-padding`. Радиусы — `--radius-*`; не дублируйте числа в компонентах.
- Текст интерфейса — 0.875rem, подписи — 0.8125rem, заголовок окна — 1.1875rem. Используйте `--text-*`; основной текст имеет межстрочный интервал 1.5, переносимый текст — не меньше 1.4.
- Pixeloid Sans поставляется с начертаниями 400 и 700. Не задавайте промежуточные веса. Сохраняйте настройки системного и локального шрифта.
- Кнопки допускают перенос длинных переводов. Пути и имена файлов переносятся через `overflow-wrap`. Счётчики используют `font-variant-numeric: tabular-nums`.
- Сохраняйте видимый клавиатурный фокус. Наведение оформляйте под `@media (hover: hover)`. Нажатие активной кнопки: scale 0.96, 150 ms ease-out; отключённая кнопка не двигается.
- Движение допускается только при `prefers-reduced-motion: no-preference`. Переключение темы отключает цветовые переходы. Прокручиваемые окна используют `overscroll-behavior: contain`.

## Компоненты и компоновка

Используйте `Dialog`, `Button`, `ActionGroup`, `StatusPanel` и `Progress` из `src/components/common`. Старые CSS-классы кнопок допустимы: они используют ту же тему.

Окно содержит заголовок, при необходимости краткое описание, содержимое и `footer` с действиями. Футер отделён границей, кнопки имеют отступ 8 px и переносятся. Основное действие одно; закрытие окна и отмена операции — разные действия. Закрытие прогресса не должно прерывать работу в фоне.

```tsx
function ExampleDialog({ open, onClose }: { open: boolean; onClose: () => void }) {
  const t = useUiText();
  return <Dialog open={open} title={t("installation.installNamed", undefined, { name: "Example" })}
    onClose={onClose} footer={<Button onClick={onClose}>{t("common.close")}</Button>}>
    <StatusPanel tone="info" title={t("common.loading")}>
      <Progress label={t("common.loading")} value={null} />
    </StatusPanel>
  </Dialog>;
}
```

## Настройки и плитки

Страницы настроек используют ширину до 1440 px; боковое меню остаётся на выбранной игроком стороне. Для связанных переключателей и коротких параметров используйте `tileGrid` и `SettingRow` из `SettingsPage`. Плитка содержит название и описание сверху, элемент управления снизу. Сетка автоматически переходит в один столбец на узком окне; высота растёт вместе с текстом. Длинные пути, выбор шрифта и действия с языковыми файлами остаются широкими блоками.

Пресеты темы — отдельные плитки с образцом палитры, названием и отметкой выбора. Базовая высота плитки настройки — 162 px, пресета — 176 px; размер текста не зависит от размера плитки. Длинный текст может увеличивать высоту.

Бета-переключатели компактного меню и верхней панели находятся во «Внешнем виде». «Компактное меню»: Off — строки, On — плитки, без изменения шрифта. Для совместимости `general.compactSettings=true` по-прежнему означает строки, а состояние тумблера в интерфейсе инвертировано; верхняя панель сохраняется отдельно в `general.compactHeader`. Скругление и плотность сохраняйте и применяйте сразу при изменении; радиус 0 означает прямые углы, включая крупные панели. Новые блоки настроек должны поддерживать оба вида. В «Дополнительно» сначала располагается автоматическая проверка обновлений, затем версия, ручная проверка и сведения о состоянии. `SettingRow` передаёт своё название переключателю для чтения с клавиатуры и экранным диктором.

Строки аккаунтов имеют высоту от 128 px и аватар 68×68 px. На узком окне действия переходят в отдельный ряд, сведения о провайдерах — в один столбец.

Составным элементам управления, например выбору шрифта с кнопкой или имени группы с действием, выделяйте широкую колонку через `fontSettingRow` или `formSettingRow`. Переход к одному столбцу зависит от ширины контейнера `settings`, чтобы учитывать боковые меню и масштаб окна. Не уменьшайте шрифт для подгонки: переносите кнопку под поле. У нативного списка подпись не переносится; оставляйте место для текста, внутренних отступов и стрелки.

## Переводы и терминология

Библиотека поддерживает три сохранённых вида: `grid`, `icons`, `list`. В `icons` используйте тот же `InstanceCard`, группы и обработчики выбора/переноса: значок 64×64 px, имя под ним с переносом, меню действий и прогресс остаются доступными. Палитра выделения общая; цвета пользовательских значков не меняйте. Панель действий библиотеки переносится, чтобы переключатели вида оставались доступны в узком окне.

Минимализм скрывает только элементы `data-minimal-text`. Навигационные значки становятся 28×28 px, компактные действия — 26×26 px. Важные короткие названия отмечайте `data-minimal-title`: в минимализме они имеют размер 1rem и межстрочный интервал 1,4. Крупные заголовки этим атрибутом не уменьшайте. У навигации сохраняйте доступное имя и подсказку.

В минимализме плитки настроек не резервируют место под скрытое описание: высота определяется названием и элементом управления, отступы и расстояние между ними — 12 px. Образцы палитр имеют высоту 48 px; увеличенные названия сохраняются. Это оформление не меняет отдельную настройку компактного меню.

Перенос сборки выполняется при зажатой основной кнопке и движении от 8 px. Захватывайте указатель на карточке, используйте координаты для определения группы под курсором и снимайте захват при отпускании или отмене. Не выбирайте сборку побочным щелчком после переноса. Следующее отдельное нажатие должно работать сразу. Активные установки не переносите; меню действий остаётся независимым.

Поиск сборок на главной использует `HomeDiscoverSearch` в обоих видах главной страницы. Строка содержит поле, небольшие переключатели сервисов и кнопку «Обзор». Отправка открывает `/discover?type=modpack&source=…&query=…`; кодируйте параметры через `URLSearchParams`. Явные параметры поиска имеют приоритет над запомненными фильтрами. Названия провайдеров и их значки сохраняют исходное оформление.

На красивой главной поиск располагается в отдельной панели над последней сборкой. Фокус поля обозначается общей внутренней обводкой строки; внешняя прямоугольная обводка вложенного поля отключается. Порядок сборок хранится в `general.instanceOrder`: неизвестные идентификаторы не выводятся, новые сборки добавляются в конец по дате создания. Перенос внутри раздела показывает место вставки до или после соседней карточки, в таблице — до или после строки. Отпускание на самой переносимой карточке не меняет порядок. Алфавитную сортировку поверх сохранённого порядка не применяйте.

- Все собственные тексты SLH имеют стабильные ключи в `resources/languages/en-US.json`; RU и DE содержат тот же набор и параметры. Новый ключ добавляется одновременно в три каталога.
- `useUiText()` и `useI18n().t` подписывают компонент на изменения языка. `t(key, fallback?, params?)` переводит целое сообщение. Не собирайте предложения из переводимых фрагментов.
- Для счётчиков используйте объект `one/few/many/other` и числовой параметр `count`; категории выбирает `Intl.PluralRules`. Числа, даты и единицы форматируйте через `Intl` с выбранным языком.
- Старый `tr` и `legacy` — адаптер совместимости. Не добавляйте новые строки через замену DOM или пересоздание дерева React. `src/i18n/sources.json` связывает старые английские строки с ключами; существующие соответствия не меняйте без миграции.
- RU: «сборка», «установить», «скачать», «повторить», «закрыть». EN: instance, modpack, install, download, retry, close. DE: Instanz, Modpack, installieren, herunterladen, erneut versuchen, schließen.
- Ошибка сообщает, что произошло и что делать дальше. Технические подробности находятся в раскрываемом блоке; не показывайте английские префиксы Rust как основную инструкцию.
- Пользовательские языки находятся в `data/languages`. Обновление не должно сбрасывать ввод, навигацию, окно или выполняющуюся установку.

## Каталог, создание сборки и короткие уведомления

`AutoFitTitle` при включённом `appearance.fitProjectTitles` уменьшает название по 1 px, пока целые слова не помещаются по ширине. Перенос между словами сохраняется; минимальный размер — 10 px. Пересчитывайте размер при изменении ширины и загрузке шрифта. Не запускайте повторную подгонку от изменения высоты: это создаёт цикл `ResizeObserver`. Названия проектов остаются содержимым провайдеров.

Категории загружайте через `list_content_categories` отдельно для провайдера и типа содержимого. Передавайте выбранный идентификатор в поиск и включайте его в ключ кеша. При смене провайдера или типа сбрасывайте категорию; не отправляйте идентификатор одного сервиса другому. Modrinth использует `categories` в facets, CurseForge — `categoryId`. Документация: https://docs.modrinth.com/api/operations/searchprojects/ и https://docs.curseforge.com/rest-api/.

В создании сборки имя и группа находятся рядом с небольшим значком. Нажатие значка раскрывает выбор изображения и цветов; при наведении и клавиатурном фокусе показывайте карандаш. Escape закрывает редактор, сохраняя форму. Последний пункт списка групп — «Создать группу…». Его выбор раскрывает поле имени; Enter или кнопка создают группу, выбирают её и закрывают поле. Сам пункт создания всегда остаётся внизу списка. Кнопки создания и отмены передавайте в общий футер `Dialog`, доступный независимо от прокрутки. Значения памяти берите из актуальных настроек Minecraft при открытии, а не из первого рендера компонента. Импорт без собственных значений памяти также использует эти настройки; экспортированные параметры существующей SLH-сборки сохраняются.

Все разделы настроек используют общие строки `SettingRow`, которые объединяются в плитки. Фрагменты React также обрабатываются. Широкие формы оставляйте отдельными строками. Помните о совместимости: сохранённое `general.compactSettings=true` означает строки, а тумблер «Компактное меню» отображает Off; On показывает плитки. Меняйте компоновку списков аккаунтов, сред Java и хранилища вместе с остальными разделами.

Короткие уведомления создавайте через `pushToast({brief:true, title:ключ, params, ...})`. Они находятся внутри SLH, показываются 2000 мс и заменяют предыдущее короткое уведомление. Настройка `notifications.briefEnabled` независима от обычных уведомлений. Сообщайте о масштабе после успешного сохранения, только если значение изменилось. Передавайте ключ и параметры для обновления текста при смене языка.

Minecraft хранит размер окна, полноэкранный режим, память и отдельные аргументы JVM. Один аргумент — одна строка; пробелы внутри аргумента сохраняются. Java хранит автопоиск, автозагрузку, проверку совместимости и предупреждение о свободной памяти. Ручной путь сборки имеет приоритет над общим. Переменная `permGenMb` применяется только до Java 8. Отключение проверки версии не отключает проверку архитектуры. Выход после игры выполняется после сохранения истории и завершения синхронизации последней Java-сборки. Эти параметры должны менять запуск в ядре, а не только отображение интерфейса.

## Проверка перед завершением

Запустите `npm run check:ui`, `npm run build`, `npm test`, Rust-тесты и соответствующие Playwright-сценарии. Проверьте окно 800×560 и 1440×900, RU/EN/DE, светлую и тёмную палитры, длинные строки, масштаб 200%, Tab/Escape и уменьшенную анимацию. Новые исключения для неизменяемого содержимого объясните в `scripts/ui-audit-exceptions.json`. Не ослабляйте проверку ради прохождения тестов.


Фильтры каталога заполняют всю ширину: четыре равных поля и переключатель снимков версий. Не используйте auto-fit с заголовком, который занимает все колонки: он сохраняет пустые колонки и оставляет поля узкими. В узком окне переключайтесь на две или одну колонку.

Парные числовые поля ширины и высоты окна используют отдельный класс `resolutionControl`: две колонки `minmax(0, 1fr)` с одинаковыми размерами. Не применяйте к ним компоновку «поле + кнопка» с колонкой auto. Равенство размеров сохраняется в строках, плитках и узком окне.

Вся карточка `SettingRow`, содержащая один `Toggle`, переключает его при нажатии на название, описание или свободную область. Нажатия на вложенные элементы управления не запускают обработчик карточки повторно. Клавиатура использует существующий доступный switch; отключённые настройки не получают расширенную область нажатия. Смешанные формы с полями, списками и кнопками остаются независимыми.


## Библиотека локальных серверов

Серверные формы используют общие `SettingRow`, `SettingGrid`, `SettingLayout` и `Toggle` из `src/components/settings/SettingControls.tsx`. Раздел «Серверы» в настройках показывает параметры по тематическим блокам; короткие поля и переключатели поддерживают те же плитки, строки и минимализм, что остальные настройки. Длинные пути и аргументы остаются широкими строками. Блокировка fieldset работающего сервера распространяется и на нажатие по свободной области строки переключателя.

Вкладки формы создания используют пиксельные иконки и нижнюю линию акцента, а действия остаются в общем футере Dialog. Выбор карточки сервера выделяется сразу; появление боковой панели кратко откладывается, чтобы изменение ширины и перенос заголовка не сдвигали карточку между двумя нажатиями двойного щелчка.

Серверы используют общие поверхности `LibraryChrome`, виды карточек, панель действий и боковую панель библиотеки сборок. Статус находится в содержимом карточки; меню действий не перекрывает его и не открывает сервер двойным нажатием. Логические группы не перемещают папки на диске. Перенос использует порог 8 px и показывает вставку до или после элемента.

Вкладки сервера настраиваются через ПКМ по панели или Shift+F10: видимость и порядок, как во вкладках сборки. Сторона панели выбирается только в общих настройках лаунчера; на странице сервера и в контекстном меню нет элементов выбора положения. Порядок можно менять переносом и Alt+↑/↓ в меню. Последнюю видимую вкладку скрыть нельзя. Порядок и видимость хранятся отдельно от сборок в `serverLibrary` (`tabOrder`, `visibleTabs`); без `visibleTabs` доступны все вкладки. Положение берётся из общих настроек, сохранённый ранее `tabsPosition` больше не применяется.

Каталог плагинов и каталог содержимого сборок используют `ContentCatalog`; журналы сервера и Minecraft — `LogViewer` и общую палитру консоли. На узком окне консоль прокручивается вместе со страницей: журнал и поле команды не должны накладываться друг на друга.


### Ядро Leaf и списки игроков сервера

Leaf получает версии и сборки из официального API Leaf v2. Экспериментальные сборки используют общий фильтр предварительных версий; установка закрепляет номер сборки и проверяет SHA-256. Leaf поддерживает каталог Bukkit/Paper-плагинов и те же ограничения путей, что Paper.

Раздел «Игроки и доступ» объединяет стандартный белый список, операторов, баны игроков и IP. Изменения записей требуют подтверждения и применяются сразу: при остановленном сервере — через файлы, при работающем под управлением SLH — через стандартные команды Minecraft с ожиданием записи результата сервером. При запуске подтверждённое изменение ждёт готовности host; при остановке или потере управления команды недоступны. Навигация и чтение остаются доступны. Ручной UUID и произвольный уровень OP доступны после остановки. Повреждённые JSON-файлы не перезаписываются; проверка ревизий сохраняется.

При добавлении игрока тип аккаунта определяется автоматически; селектора провайдера в форме нет. Запрос использует identityProvider: auto, разрешение имени выполняет ядро с учётом режима сервера. При работающем сервере игрок определяется сервером по нику. Плагины могут использовать отдельные списки.

## Проверка готовности интерфейса

Найдите ближайший завершённый экран SLH и сравните композицию, действия и состояния. Используйте существующие компоненты и токены, а новые строки добавляйте одновременно в EN/RU/DE. Проверьте узкое и широкое окно, длинный текст, локализацию, тему, фокус, клавиатуру, reduced motion и затронутые состояния. Сохраните визуальные доказательства и укажите намеренные исключения и непроверенные сценарии.

### Настройки локальных серверов: подразделы и расположение

Основные вкладки рабочей области остаются прежними. Внутри настроек используйте переключаемые подразделы `ServerConfigFields`, первым открывайте «Игроки и доступ». Не блокируйте общий контейнер вместе с навигацией: недоступны только поля параметров, требующих остановки. Белый список работающего сервера применяется сразу; на остановленном — вместе с сохранением параметров.

Положение вкладок сборок и серверов, боковых панелей и главной навигации меняется только в общих настройках лаунчера. На страницах серверов нет блока «Server layout»; старые локальные переопределения расположения не применяются и не удаляются из пользовательских данных. Ctrl-перетаскивание главного меню больше не меняет сторону навигации. Порядок содержимого и видимость вкладок остаются отдельными действиями.

Решение, источники и границы проверки: `docs/local-server-settings.md`.


### Обновление 1 ноября: работающий сервер и память

Подраздел «Управление миром» добавляет runtime-настройки через команды Minecraft: сложность, режим по умолчанию, idle timeout, время, погоду, границу, сохранение и gamerules с учётом версии. Отображать реальный вывод сервера; отправку команды не называть подтверждённым изменением. Списки доступа ориентируются на свежий runtimeState из ядра. При запуске формы доступны, применение ждёт готовности host; при остановке и потере управления команды недоступны. Это заменяет прежний запрет редактирования в состоянии starting.

Java-память редактируется вручную двумя числовыми полями от 128 МиБ, включая при работающем сервере. Отдельное сохранение меняет только параметры следующего запуска в профиле, не текущую JVM и не файлы сервера. В обзоре использовать ключ `serverLive.memoryOverview` («Память ОЗУ (МиБ)»). Horizon не имеет JVM-лимитов; показывать автоматическое управление. Использовать существующие SettingRow/Grid, Dialog, Button, tokens и ряд/плитки. Границы и фактические результаты: `docs/local-server-settings.md`.

Проверка панели Horizon и формы игроков: 800×560 и 1440×900 в браузерном предпросмотре; длинные значения в боковой панели переносятся, поле UUID отсутствует, выбор OP применяется без дополнительного подтверждения. Работающий сервер сам разрешает имя и подтверждает изменения через свои списки; для неизвестных офлайн-игроков может понадобиться первый вход. Интеграция Ely.by на действующем сервере зависит от его системы авторизации и в предпросмотре не проверяется.

### Подтверждения и системное оформление

Подтверждения удаления используют общий Dialog и general.confirmDestructiveActions, по умолчанию включённый. Тумблер не отключает ошибки, ограничения совместимости и защиту синхронизации миров. Резервные копии и корзина в рамках UX-аудита не добавляются.

Управление окном по умолчанию соответствует платформе. general.platformCustomization открывает во «Внешнем виде» системные списки, стиль и сторону кнопок окна. Выключение сохраняет значения, но возвращает системное оформление. Цвета смешиваются в коде темы и сборки для совместимости со старым WebKit.

Редкие инструменты переводов и ручные настройки доступны в раскрываемых группах. Широкие поля внутри групп занимают всю строку. Обязательные ограничения и ошибки не прячьте в раскрытиях.
